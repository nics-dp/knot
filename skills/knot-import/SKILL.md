# 把原始資料匯入 Knot

Knot 是使用者撰寫報告的工具。撰寫本文時，agent 只看得到每段的意圖與它的**依據**：掛在這一段上的素材與事實。這一步的工作就是準備這些依據：

- **素材：** 從原始資料照抄的一段原文（節錄），或照原樣的一張數據表（表格素材），附上來源檔名與位置，讓使用者能回頭核對。
- **事實：** 本文會寫到的數字與關鍵值，指向它所屬的素材。Knot 會檢查值確實出現在素材中，本文以 `{{fact:key}}` 引用，值只存一份。
- **依據：** 把素材掛到需要它的段落或引言上（`add_citation`），撰寫時才會出現在撰寫參考裡。

Knot 不讀原始檔、不保存原始檔；讀檔、挑選與照抄都由你負責，使用者會抽查。

## 開始之前

1. `get_outline`（`full_intent: true`）看卡片與意圖。還沒有卡片時，告訴使用者先規劃（規劃 skill）；使用者堅持先匯入時，依 `撰寫要求.md` 與資料本身判斷要節錄什麼。
2. 報告目錄有 `撰寫要求.md` 時讀它：每條 R 的來源（檔名與位置）就是要節錄的地方。
3. `search_sources`（`query: ""`）看已經有哪些素材；回傳的 `sources` 列出每個來源檔已有幾筆。`list_facts` 看已有的事實。已經匯入過的檔案不要重複匯入，只補缺的。
4. 列出報告目錄的檔案（略過 `.knot/`、`export/`、`撰寫要求.md`），告訴使用者你要匯入哪些、大約多少筆，然後開始。檔案很多時一次處理一份，每份做完回報一次。

## 讀檔

- 用你能用的方式讀：文字檔、Markdown、CSV 直接讀；PDF 可以直接讀（頁數多時分段讀，記下頁碼）；Excel 可用 Python（`openpyxl`、`pandas`）讀出工作表。讀不了的檔案告訴使用者，請他轉成 PDF 或文字。
- 位置要記得精確：頁碼、章節編號與標題、會議紀錄的案由與點次、工作表名稱與列範圍。

## 節錄（`add_excerpts`）

**挑什麼：** 意圖或 R 會用到的內容：目標、範圍、規定與標準、決議、委員意見、結論、原因、限制、問卷或訪談的結論。不是整份照搬；與報告無關的段落不節錄。

**照抄原文：**

- 不改字、不改數字、不改標點，不摘要、不改寫、不翻譯、不補字。
- 可以去掉的只有排版造成的東西：PDF 斷行、頁首頁尾、頁碼、行首的項目符號（•、-），以及 Markdown 標記（`**粗體**`、`#`、`>`）。
- 一段只講一件事，通常是一到數句。原文中間不相連的兩處，分成兩筆，不要用「⋯」接起來。
- 條列：整串一起節錄時照原本的順序與編號（1.、（一））抄；只節錄其中一項時，不抄編號，把它寫進 `location`（「案由三 第 3 點」）。

**每筆的欄位：**

- `source`：檔名，含副檔名，與報告目錄中的檔名完全相同（例如「主管會議紀錄.md」）。同一份資料始終用同一個名稱。
- `title`：一眼看出這段講什麼（「成功標準」「個資遮罩決議」），不要用「段落 3」。
- `location`：例如「第 3 頁」「三、試行範圍」「案由三 第 2 點」。
- `note`：用途，寫要給哪些卡片或哪條 R 用（例如「4.1 正確率判定方式；R5」）。

一次最多 50 筆，同一份檔案的節錄盡量一次送出。整批不合法時 Knot 會列出每一筆的問題，修正後整批重送。

## 表格素材（`add_source_table`）

- 原始資料裡的數據表（CSV、Excel 工作表、PDF 中的表）**照原樣**節錄：欄名、列序、儲存格的寫法（單位、百分比符號、千分位）都照抄，不排序、不合計、不換算、不刪欄。
- 表很大時（例如上百列），只節錄報告用得到的列或欄，但仍照原樣，`location` 寫明範圍（「第 5–12 週」「工作表 2，A1:F40」），`note` 說明取了哪些。
- 你重新整理或計算過的表不是素材，是報告中的表格卡片，撰寫時用 `write_table` 寫。
- 圖與表格卡片要用的數據，就是表格素材本身，不必逐格記成事實；事實只記本文文字會寫到的數字。

## 事實（`add_facts`）

**哪些數字要記成事實：** 段落意圖、R 會寫到的數字與關鍵值：人數、件數、比率、金額、期間、門檻與目標值、日期。素材中的每個數字不必都記，表格的每一格也不必（見上）。

- `value` 照抄素材中的寫法（原文「1,437」就寫 "1,437"；日期照抄「2026 年 6 月 1 日」）。單位一律分開記：原文「89.8%」「18%」記成 value "89.8"／"18"、unit "%"；「6.8 小時」記成 value "6.8"、unit "小時"。
- 表格素材的值要指定 `row`（0 起算）與 `column`，避免比對到別的儲存格。
- `key`：小寫英文、數字、`.`、`-`，依主題分層，例如 `accuracy.week-12`、`survey.responses`、`baseline.first-response-hours`。同一系列用一致的命名。
- `label`：中文顯示名稱，看得出是哪個值（「第 12 週正確率」）。
- 一次最多 100 筆；Knot 比對不到值時整批拒絕並說明，修正後重送。

**計算出來的數字不是事實。** 意圖裡有你或規劃時算出來的數字（合計、平均、增減幅度），先找資料中是否本來就寫著這個值（例如會議紀錄或報表已經算好）：有就節錄那一段並記成事實；沒有就不要硬記，在回報中列出「意圖要用、但只能計算得到的數字」與計算所需的事實，讓使用者決定。

**使用者口頭提供的事實**（`撰寫要求.md` 中來源為「使用者提供」的）不在任何檔案裡，不能當素材。請使用者把它寫成報告目錄中的一份檔案（例如 `補充說明.md`，寫明是誰、何時提供的），再從那份檔案節錄。

## 掛到段落上（`add_citation`）

素材與事實都建好後，逐段對照意圖：

- 每個有內容要依據的段落與引言，用 `add_citation` 掛上它需要的素材（表格與圖卡片不能掛依據，掛在介紹它的那一段）；只用到表格的一部分時，`where` 寫範圍（「欄：週次、正確率；第 5–12 週」）。
- 一筆素材可以掛在多段上；一段可以有多筆素材。
- 意圖要求的內容找不到任何素材時，不要掛不相干的素材湊數，在回報中列出這一段。
- 掛完後再 `get_outline` 一次：段落與引言的 `citations` 是依據數，逐一檢查 0 的卡片是否確實沒有資料可用。

## 一致性

- 每份檔案一個 `group`（例如「匯入：主管會議紀錄.md」），這份檔案的節錄、表格素材與事實都放在這一組，使用者可以逐檔檢視與復原。掛依據另成一組「掛上依據」。
- 資料之間互相矛盾（同一個數字兩份資料不同）時，兩邊都節錄，在回報中列出，不要自己選一個。
- 資料與意圖不一致（意圖寫 95.9%、資料是 95.8%），或意圖寫了資料中沒有的內容（例如意圖要求註明期間與出處，資料卻沒寫）時，以資料為準記事實，並用 `add_note` 在該卡片留言說明，不要改意圖。

## 新增或更新了資料

使用者說「新增了一份資料」或「某某檔更新了」：

- **新檔案：** 只匯入這份，同上。
- **更新過的檔案：** `search_sources`（`source` 為該檔名）列出它已有的素材，逐筆對照新檔：原文改了的用 `update_source_block` 修正（Knot 會回報值對不上的事實，用 `update_fact` 修正）；新檔已刪除的內容，先看 `get_source_block` 的 `cited_by`，被引用的列出來問使用者，沒被引用的用 `discard_source_block`。檔名改了（例如加上日期）時，在回報中說明新舊對應。

## 回報

結束時用幾行告訴使用者：

- 每份檔案新增了幾筆節錄、幾張表格素材、幾筆事實。
- 掛了依據的段落數；**沒有任何依據的段落**與原因（資料沒有、等使用者提供）。
- 意圖要用、但只能計算得到的數字。
- 資料之間的矛盾、資料與意圖不一致之處（留了留言的卡片）。
- 讀不了或刻意略過的檔案。
- 下一步建議：請使用者在 Knot 的「素材」頁抽查幾筆原文與來源，再開始撰寫本文（撰寫 skill）。
