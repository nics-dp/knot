# 試寫紀錄：OO 市北區社區共享單車試辦計畫成果報告（2026-10-29）

第一次完整試寫。主對話（Opus）扮演使用者，Sonnet 扮演 agent，只透過 MCP 操作 Knot 和讀取原始資料，目的是找出缺少的功能。案例與原始資料全部虛構。

## 設定

- **報告目錄：** `local/trial-report`（不進 git）。原始資料放在 `sources/`，共 5 份：
  - 計畫書：緣起、目標、範圍（20 站、120 輛）、期程、4 項績效指標、經費
  - 期中審查會議紀錄：4 條委員意見，期末報告須回應
  - 營運數據.csv：114 年 4–12 月的站點數、車輛數、騎乘人次、會員、妥善率
  - 問卷調查摘要：滿意度、年齡別使用情形、不滿意原因
  - 成果報告格式：交通局規定的三章
- **刻意埋的判斷點：** 月平均騎乘 2,871 未達 3,000；滿意度 78.4% 未達 80%；乙里 2 站延後設置；委員要求分期呈現數據。
- **條件：** 還沒有寫本文的工具（M6）與素材匯入（M5），所以只試規劃結構、意圖、關係、留言與待辦、歷程。
- **做法：**
  - REPL 以 `(user/use-report! "local/trial-report")` 把執行中的伺服器切到試寫報告，結束後 `(user/use-report!)` 切回。
  - agent 以 scratchpad 裡的 `knot-mcp` 腳本（curl 包 JSON-RPC）呼叫 `/mcp`。

## 經過

1. **第一輪，規劃大綱：** agent 讀資料後以 `build_outline` 一次建好三章 38 張卡片，每段寫意圖，設 15 條相鄰關係與 17 條遠距關係，留下 7 則提問。刻意埋的判斷點都問到了。
2. **使用者回覆：** 回答 7 則提問（部分給了資料裡沒有的事實，例如 12 月下雨、系統更新停機），交代 2 個待辦（合併兩段、結語回扣三個目標），決定期中意見不獨立成節，並自己改了一段意圖但沒有告訴 agent。
3. **第二輪，依回覆與待辦調整：** agent 更新意圖，刪除獨立的「期中審查意見回應」節並把意見分散到各段，兩個待辦都完成並回覆。它比對所有卡片的版本號，從修改紀錄發現使用者改過的意圖並保留。結語又留了一則提問（目標二缺佐證）。
4. **第三輪，加深到四層：** 把「營運數據分析」分成項與款（2.2.1.1、2.2.1.2）、「擴大辦理建議」分成三項，並把一整項連同段落搬到另一節。四層的編號、卡片頁五欄、全文頁大綱都正確。第五層用 `add_card`、`move_card`、`build_outline` 三種方式都被擋下，錯誤訊息清楚。

結果：三章 48 張卡片，最深到第四層。

## 發現的缺口

### A. 寫不出成品（M5、M6 範圍）

1. 沒有寫本文的工具。agent 準備好撰寫流程（依序取撰寫時參考的內容、對照原始資料、核對計算），但無法存入。
2. 無法登記素材與引用：agent 只能在意圖裡寫「素材：計畫書 二」，意圖變長，也無法被檢查。
3. 無法建立表格與圖的卡片：`add_card`、`build_outline` 只收標題、段落、引言，「指標達成總表」只好用段落代替。

### B. 調整結構很費工

1. **每次寫入是一個修改組：** 一輪約 40 次寫入，歷程裡就有 40 筆，無法一次復原。
2. **已有段落的標題底下不能直接加下層標題：** 標題的下層要嘛全是段落、要嘛全是下層標題（不能混放）。要把「2.2 營運數據分析」底下的段落分到 2.2.1、2.2.2，沒有「把這幾段包進新標題」的工具；agent 先建一個暫存章、在裡面建新標題、把段落搬進去、再把新標題搬回原處、刪掉暫存章，歷程多出建立與刪除暫存章的紀錄。
3. **沒有合併卡片的工具：** 合併兩段要改一段、刪一段、重設關係，agent 還漏刪一次（標完成後才補刪）。
4. **相鄰關係不能跨標題：** 遞進、因果等相鄰關係只能設在同一個標題底下前後相接的段落。段落被包進不同的新標題後，原本的相鄰關係消失也無法重設；小節之間的銜接（1.1 的最後一段到 1.2 的第一段）只能用遠距關係，而遠距關係沒有遞進與因果。
5. 刪除卡片的回傳不列出被移除或轉為待確認的關係；搬移後要逐張 `get_card` 才找得到待確認的關係。
6. `move_card` 的回傳訊息用移動前的編號。
7. 相鄰關係的錯誤訊息沒有提示操作順序（要先刪掉中間的卡片）。

### C. agent 與使用者的溝通

1. **agent 處理使用者的回覆後沒有在討論串接話，** `list_todos` 的 `questions_answered` 一直列出這些討論串。說明沒有寫清楚怎樣算接話。
2. **工具回傳的名稱帶編號**（「第一章 計畫概述」），agent 以為編號存在名稱裡，擔心改名或移動後重複。
3. **沒有報告層級的設定：** 報告名稱停在目錄名稱「trial-report」，副標空白；MCP 沒有工具，畫面也改不了。篇幅目標（格式要求 10–15 頁）沒有地方記。
4. 偵測使用者的改動要比對所有卡片的版本號；希望有「某個修改組之後的變動」。
5. 提問只能是純文字；一則問三件事，回答也只能用一則文字回三件。希望提問可以附選項。
6. `get_outline` 的意圖截斷為 80 字，要看完整意圖只能逐張 `get_card`。
7. `add_note` 回傳不含卡片資訊。

### D. 使用者審閱

1. **全文頁看不到意圖：** 還沒有本文的段落只顯示「（尚未生成：名稱）」，審閱大綱只能逐張點開。
2. 全文頁大綱第四層的名稱被截斷；全文第三、四層標題的字級差異小，層次不明顯。
3. agent 為了遵守混放規則自行決定結構（把結語包進新的 3.3、把 2.1 的段落各包進 2.1.1、2.1.2），在回報中有說明，但畫面上看不出這是 agent 的判斷。
4. 「2.2 營運數據分析」搬走一項後只剩一個項，結構不平衡（agent 有提出）。

### 好用的地方（agent 的回饋）

- `build_outline` 一次建好整棵樹，回傳每張卡的 id 與編號。
- 錯誤訊息具體：指出是哪張卡片、什麼規則（例如「已經是第四層，不能再新增下層標題」），並建議改用的工具。
- 整項搬移並自動重算編號。
- `get_card` 的 history 與 notes 可以確認寫入結果、發現使用者的改動。
- `complete_todo` 附回覆、`add_note` 的 `reply_to` 接討論串很直覺。

## 試寫中修正的問題

- 待辦面板的長提問文字疊在一起（清單項目被壓縮）：項目不壓縮、說明最多兩行。
- 伺服器重啟或切換報告後，開著的頁面停在舊資料：事件連線重連後重新讀取。
- shadow REPL 的 `cljs-eval` 指定分頁要用 `:runtime-id`（`:client-id` 會被忽略，結果送到使用者的分頁）；已寫進 CLAUDE.md。

## 第二輪：撰寫全文初稿（M6 後）

M6 加入 `write_prose`、清單、表格與圖卡片後，以同一份試寫報告請 agent 撰寫全文初稿：23 段與 4 個引言，建立 `tab:scope`、`tab:kpi` 兩張表與 `fig:ridership-trend` 一張圖，全部歸在「撰寫全文初稿」一組。先前使用者回覆的 7 則提問都寫進本文並在討論串接話；另留 4 則提問（意圖中查不到出處的數字、妥善率重算為 95.8% 與意圖不符、自行加的表格要不要留、趨勢圖待製圖）。

agent 回報的問題與處理：

- **未綁定的數字太吵：** 報告沒有事實時每段都列出一串，連年月、章節編號都算。→ 沒有事實時不提醒；年、月、日與章節編號不算。
- **參數名稱不一致：** `get_card` 用 `id`、`add_note` 用 `node_id`。→ 卡片一律 `card_id`、留言一律 `note_id`，舊名稱回清楚的錯誤。
- **撰寫參考重複多：** → 周邊卡片一律只帶意圖並標明是否已有本文，需要時以 `get_card` 取本文；引言仍帶下層本文。
- 試寫後另加入字數與目標字數（看板、編輯區、MCP）。

- **意圖截斷、只能逐張讀卡片：** → `get_outline` 加 `full_intent`，新增 `get_cards`（一次最多 30 張）。

尚未處理：表格儲存格不能引用事實或加粗。

## 第三輪：建立素材與事實（M5 後）

素材改為 agent 從原始資料節錄後以 MCP 新增（Knot 不轉換原始檔）。agent 從 5 份原始資料建立節錄 24 筆、表格 7 張、事實 62 個，並把第二章 11 段的數字改成事實引用、標出依據；初稿中 4 處找不到出處的內容沒有編造素材，留言請使用者確認。

agent 回報的問題與處理：

- **事實值檢查誤放行：** 「12」被當成出現在儲存格「1210」中。→ 數字要完整對上（數字邊界），表格逐格比對。
- **沒有刪除事實的工具：** → 新增 `delete_fact`（本文還用到時拒絕）。
- **顯示與千分位：** chip 顯示「3760人次」。→ 顯示時四位數以上整數加千分位、數字與中文單位間空一格；比對忽略千分位。
- **一筆一筆新增太慢（100 多次呼叫）：** → `add_facts`、`add_excerpts` 批次工具。

尚未處理：`[[cite:...]]` 只認 id；「未綁定的數字」可提示哪些剛好等於某個事實的值。

## 第四輪：撰寫參考帶前一段與依據目標的本文（對照試寫）

要驗證的問題：段落之間應該是前面影響後面；撰寫參考帶前一段（不論關係類型）與依據目標的本文，並依 `get_writing_order` 的順序撰寫，品質是否比「周邊一律只帶意圖」好。

做法：兩個全新的 agent 各自依 `get_writing_order` 的 5 批順序，從頭重寫第二章 14 張卡片（12 段、2 引言），不看舊本文。

- **對照組（試寫 4B）：** 以包裝腳本把撰寫參考中前一段、依據目標的本文換回意圖，模擬舊做法；可以用 `get_card` 讀本輪已重寫的卡片（實際只讀了 2 張，為了寫引言）。
- **實驗組（試寫 4A）：** 新的撰寫參考；`get_card` 0 次。

第三個 agent 不知道版本來源，盲評兩份第二章。

**結果：實驗組略好，差距小。**

- **實驗組較好：** 跨段與跨節的銜接（2.3 總表轉入未達成說明、2.4 開放意見扣回 2.1.3 的電輔車比較與年齡別分析）；電輔車「每車使用率」限定為 6 月起，與數據一致。
- **對照組較好：** 重複較少（實驗組在節引言先講了 12 月回落原因，下段又講一次；「依委員意見增列年齡別分析」寫兩次）。
- **兩組都有：** 加入意圖與素材沒有的說法（實驗組「系統更新時程宜避開服務期間」，對照組「站點加密後」）。

**限制：** 兩組都由同一個 agent 依序寫完整章，對照組 agent 表示「靠剛寫過的記憶來銜接」，撰寫參考的差異因此被 agent 的記憶抵銷一部分。新做法的效益應出現在沒有這段記憶時（分批由不同 agent 撰寫、跨對話接著寫、單獨改寫一段），這次沒有測到。

兩組 agent 回報的問題（與撰寫參考帶本文無關）：

- **引言拿不到下層本文：** 下層是小節標題時只列標題的意圖，標題底下段落的本文沒有往上帶（第二章引言、2.2.1 引言）。
- **表格素材只有欄名與列數：** 要描述趨勢或確認數值必須另外 `get_source_block`。
- **可用事實太多又不夠：** 每段都帶逐月營運數據約 30 筆事實；本段需要的目標值事實（`target.*`、`stations.planned`）因為不在依據素材上而沒有列出。
- **意圖給的計算值沒有事實可綁：** 2,871、2,667、3,585、17% 只能成為未綁定數字。
- **未綁定數字誤報：** 年齡區間 18、34，「每週 3 次」、「乙里 2 站」都被列入。
- **撰寫參考中的交互參照未轉換：** 前一段本文裡的 `{{ref:...}}` 顯示為「{fig:ridership-trend}」，看不出是哪張圖表。
- **整章重寫時 Knot 待辦成為雜訊：** 每寫一段就在稍後也要重寫的卡片留下待辦，第二章引言累積十幾則觸發。
- **`get_writing_order` 的段落沒有編號，** 看不出屬於哪一節；已有舊本文時 `has_prose` 分不出這一輪是否已重寫。
- **意圖與資料不一致：** 指標達成總表的意圖寫妥善率約 95.9%，九個月平均是 95.77%，表格 `tab:kpi` 為 95.8%。

報告目前的第二章是實驗組（試寫 4A）的版本；第三輪的本文存在試寫的暫存檔，可以從卡片歷程復原。
