# 待討論問題

每題寫明相關章節、問題、可能的選項與各自影響。定案後更新 `docs/SPEC.md`，再從本檔移除該題。

## Q1. 新增卡片與「改為引言」的介面位置（SPEC 5.3 層級）

- **目前實作：** 標題編輯區的「下層內容」提供「＋ 段落」「＋ 下層標題」；已有段落時改為「＋ 下層標題（把現有段落移入）」。段落編輯區底部提供「改為引言」（所屬標題還沒有引言時）。
- **問題：** 這些操作的位置與文字是否符合預期？設計稿沒有畫到。

## Q2. 「生成時 AI 會參考的內容」的範圍（SPEC 5.4）

- **目前實作：** 文風、章節路徑（各層標題意圖）、本段意圖、依據摘要、可用事實、前後段意圖與關係、摘要本段的段落意圖、下層表格與圖的意圖。不帶任何段落全文。
- **問題：** 「可用事實」目前列出全部事實；事實很多時是否只列與依據表格相關的事實？前一段是否需要附上本文最後一句以銜接語氣（規格已寫為「需要時」）？

## Q3. 文風與範本如何跨報告共用（SPEC 5.1、5.7）

- **背景：** 一個報告目錄只有一個資料庫，原本跨報告共用的 library 資料庫已取消。文風規則（公司 < 機關 < 專案）與報告範本仍需要在不同報告之間重複使用。
- **選項：**
  - A. 文風與範本存成 EDN 檔，放在使用者設定目錄（例如 `~/.knot/styles/`、`~/.knot/templates/`），套用時複製快照進報告。
  - B. 由使用者匯出、匯入檔案，每份報告自行保存，不設共用位置。
  - C. 從另一個報告目錄複製文風設定。
- **影響：** A 最接近原本「來源更新時提示同步」的設計；B、C 最精簡，但無法提示來源已更新。
